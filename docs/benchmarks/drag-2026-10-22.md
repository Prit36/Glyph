# Drag rendering and selection performance

Measured locally on 2026-10-22 with an Intel Core i5-12400F, native Windows x64, MSVC C++20 `/O2 /MT`. Baseline: commit `a5f1a8c`. Values below are medians of three alternating baseline/optimized runs on the same machine; timings vary with system load.

| Measurement | Baseline | Optimized | Change |
|---|---:|---:|---:|
| 4K box update, 1 px diagonal move | 317.7 µs | 157.2 µs | 50.5% less elapsed time |
| Pixels repainted per box move | 78,217 | 32,249 | 58.8% fewer |
| Damage rectangles per box move | 4 | 2 | 50% fewer |
| Full 4K repaint with a large clear box | 7.44 ms | 6.69 ms | 10.1% less time |
| Text endpoint update, 20,000 words | 186.4 µs | 0.313 µs | >99% less time in this stress case |
| Scratch bitmap on a 3840 × 2160 desktop | 3.75 MiB | 1 MiB | 73.3% smaller |

The maximum scratch allocation drops from 4 MiB to 1 MiB. The screenshot still requires 31.64 MiB for a 4K desktop. This is not a measurement of total process memory: OCR, text, Windows graphics resources, and the small toolbar surface are additional.

## What is measured

Run `./tests/drag-perf.ps1` from the repository root. The fixture generates immutable pseudo-random screenshot pixels and paints into an offscreen DIB; it neither captures nor interacts with the desktop. It measures 20 full paints, then 400 alternating diagonal moves of a box from `(100,100)` to `(3000,1800)`. Each move includes damage construction, region enumeration, and rendering. GDI is flushed before taking the final elapsed time.

The text fixture has 400 rows of 50 eight-character words. After preparing one long selection, the endpoint alternates between adjacent character boundaries in row 300 for 10,000 updates. The timer covers hit testing and selection changes; it excludes painting and native pointer tracking. This specifically tests the old cost of scanning earlier rows and rebuilding an unchanged long selection on every character movement. Large endpoint jumps still necessarily update every word whose selection changes.

For comparison, the same fixture was compiled against the baseline source extracted into the ignored `build/` directory. The fixture used the baseline damage function and `mouseMove` entry point, with its `TrackMouseEvent` call removed to exclude tracking on a hidden window. The optimized fixture calls `updateTextSelection` directly. Neither timing includes native pointer delivery, display presentation, OCR, or input-to-display latency; these results do not imply a particular FPS or monitor response time.

## Changes and correctness checks

- Damage regions reuse their native handles. Interior XOR plus sweeps of moving edges skip unchanged borders while keeping the region compact enough to avoid excessive small GDI flushes.
- A square 512 × 512 scratch bitmap balances horizontal and vertical damage, with a 1 MiB allocation limit. Clear interiors use row copies and are not blended twice.
- Character selection retains a base snapshot only when a gesture starts, then restores/reapplies only the words between old and new endpoints. The per-move scratch selection vector is removed.
- Hit testing reuses the highlight-row index, searching around the pointer's vertical position with prefix-bottom bounds for tall/overlapping rows. Equal-distance ties retain original word order; character boundaries use binary search and preserve surrogate pairs.
- Toolbar alpha shapes and their DC are reused until dimensions, scale, hover, press, focus, or enabled state change. Labels still render onto the opaque target for ClearType. Mouse-leave tracking is armed once until the pointer leaves.

`./tests/ux-smoke.ps1` verifies the real renderer and interaction state without displaying windows. Added coverage compares incremental and full paints for 486 box transitions at 100%, 125%, 150%, 175%, 200%, and 300% DPI, including tiny/empty boxes, reversals, clamping, and screen edges. It checks 3,000 indexed hits against exhaustive search, 1,800 additive/reversed text updates against full selection rebuilding, incremental highlight pixels, toolbar cache states, and stable GDI handle counts. Existing shortcut, queued copy, OCR stale/error, capture contrast, and settings checks also pass.
